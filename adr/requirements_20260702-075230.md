1. **Refactor existing deposits_payments schema files** from `CREATE TABLE X (...)` to `CREATE TABLE X_schema (...)` to match the connector + `LIKE` pattern used throughout the rest of the catalog

3. **Create production connector files** (`-prod.sqrl`) for all 7 datasets — Kafka for bronze sources, Iceberg for silver derived datasets

7. **Compile and test** using `ontology-test-package.json` to validate the complete catalog

## Scenario Analysis

**Scenario `catalog`**: The artifact being extended is a standalone data catalog — a repository of `_schema` table definitions, per-environment connector files, test data, and ontology relationship definitions. No pipeline transformation logic or GraphQL API is being added; the focus is on catalog completeness (schema documentation, governance tags, connector wiring, and ontology relationships).

**Task `extend-catalog`**: The deposits_payments LOB already has bronze/silver schema definitions in `.sqrl` files, team README files, and governance annotations (classification levels, sensitivity tags). What's missing are the connector files, test data, LOB-level ontology, and root integration. The existing files also use a non-standard `CREATE TABLE` pattern that needs refactoring to `_schema` + `LIKE` to align with the established catalog conventions from Customer and Lending.

### Key observations from workspace analysis

1. **Schema pattern mismatch**: deposits_payments `.sqrl` files define tables with `CREATE TABLE X (...)` directly, while lending and customer use `CREATE TABLE X_schema (...)` and connector files that `IMPORT x.*; CREATE TABLE X (...) LIKE X_schema;`. The deposits files must be refactored to the `_schema` pattern.
2. **ingested_at placement**: In the lending/customer pattern, `ingested_at` is NOT in the `_schema` definition — it's added in the connector file (as a NOT NULL computed column for test, or as Kafka METADATA for prod). The deposits_payments files currently include `ingested_at TIMESTAMP` in the base table definition; this must be removed from schema and added only in connectors.
3. **Timestamp type**: deposits_payments uses `TIMESTAMP` while lending/customer uses `TIMESTAMP_LTZ(3)` for `source_updated_at`. This needs alignment for consistency.
4. **Template comparison**: The finance-catalog template at `/opt/sqrl_templates/finance-catalog/` also has deposits_payments schema files only (without connectors), confirming that adding connectors/test data is the next step.

## Technical Decisions

1. **Schema pattern alignment**: Refactor deposits_payments `CREATE TABLE` definitions to use `_schema` suffix, matching the convention established by Customer and Lending LOBs. This enables the `LIKE *_schema` pattern in connector files, which separates schema definition from environment-specific connector configuration.

2. **`ingested_at` placement**: Remove `ingested_at` from all `_schema` definitions. Add it only in connector files — as `NOT NULL` with WATERMARK for test (filesystem), and as `METADATA FROM 'timestamp'` for prod (Kafka). This follows the established catalog convention.

3. **Timestamp type standardization**: Use `TIMESTAMP_LTZ(3)` consistently for `source_updated_at` and `ingested_at` across all deposits_payments files, matching the lending/customer convention. This ensures test watermarks and Kafka metadata timestamps are type-compatible.

4. **Kafka topic naming**: Follow the pattern `deposits_payments.<snake_case_table>` (e.g., `deposits_payments.transaction`, `deposits_payments.account`) using `DEPOSITS_PAYMENTS_KAFKA_BROKERS` environment variable.

5. **Iceberg catalog configuration**: Use catalog-name `deposits_payments`, warehouse `DEPOSITS_PAYMENTS_ICEBERG_WAREHOUSE`, catalog-database set to the team folder name (`accounts` or `transactions`), matching the lending pattern.

6. **LOB ontology file naming**: Use `deposits_payments/deposits_payments-ontology.sqrl` (snake_case with hyphen) to match the existing `lending/lending-ontology.sqrl` naming convention within the root ontology import path. Note: `ontolgy.sqrl` imports `lending.lending-ontology.*` — the dot-separated path maps to directory/filename, so the file is `lending/lending-ontology.sqrl`.

7. **JSONL test data file naming**: Use `<dataset>-<snake_case_table>.jsonl` (e.g., `deposit_accounts-account.jsonl`) placed in `<team>/testdata/`, matching the convention in lending.

8. **Watermark strategy**: Use `INTERVAL '10' SECOND` for filesystem test connectors and `INTERVAL '30' SECOND` for Kafka prod connectors, consistent with Customer and Lending.

9. **Silver table `computed_at`**: For silver (derived) tables, add `computed_at TIMESTAMP_LTZ(3) NOT NULL` in the connector file (not in schema), as these tables are written to Iceberg and don't have Kafka ingestion timestamps.
